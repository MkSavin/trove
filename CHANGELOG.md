# trove

## 0.2.0

### Minor Changes

- 918fa92: `trove client add claude --local` registers the MCP server for the project in the user's own Claude Code config and puts the skills into `~/.claude/skills`, writing nothing into the project; Cursor and Codex refuse `--local`. The README says when `.trove.yaml` can stay out of the project.
- e40fe3a: Clients: a Claude Code plugin (MCP server, skills, hooks that check edited documents and sync at session end), `trove client add claude|cursor|codex`, `init --client`, `trove regulation`, and single-file binaries attached to every release.
- c33e4a9: `trove refs <file|dir|glob> [--lines A-B] [--all]` lists open items and ledger-less documents in work that point at code, found the way drift finds references; MCP `trove_query` does the same with `kind: refs`. A new rule, `duplicate-suspect` (off by default), flags open items that look like one finding written twice: most words of their `what` match, or fewer when both name overlapping lines of one file.
- 8bf6e64: Plan stages are also read from a run of headings or bold paragraph labels coded like `Э1` or `Stage 2`, done by a `[x]` or `✅` mark, a done value in a trailing parenthesis or a status line under it. Stage titles and `next` lose their Markdown and keep their first sentence. The default done words cover more English and Russian forms (`released`, `слито`, `в master`, `реализовано` and others). Documents in the archive or with a status the archive keeps have no stages and leave the progress view.
- d42998f: `doctor` inside a store shows it and the project the registry ties it to; a root with a `ref` reads files git ignores from the checkout; git calls ignore the variables a git hook sets; the `item-size` rule (off by default, `limit` in bytes); a summary keeps its generated blocks as a snapshot once its date has passed.
- 43c49fe: `drift` is sharper. Items point at code through links and inline file names (`` `send.ts:41` ``, `` `composer/send.ts` ``) in their ledger row and their own section; a bare name is found with `git ls-files` and counts only when it is unique. A reference that names lines drifts only when those lines changed, read as of the last commit on or before `checked`. `drift=false` now means checked and unchanged, and `drift=unknown` covers items with nothing that could be checked; a `drift` cell shows `—` and `?` for them.
- e40fe3a: Edit operations: `doc new|archive|checked|set` and `item add|close|defer`. Each patches only its own lines (CRLF kept), is checked in memory before writing, refuses changes that add errors, and rebuilds generated reports in the same step. `--dry-run` prints the line diff.
- 6e160b5: Rule `front-matter-yaml` (warn) points at a front matter field that strict YAML readers such as GitHub reject, e.g. an unquoted value holding `: `.
- 1e16978: `trove:branches` shows each branch once, preferring the remote-tracking ref and marking a local branch that is ahead or diverged, adds an `own` column of commits in none of the bases, and hides branches merged into every base unless `merged=true|any`. `trove:changes` shows items closed as `moved` as moved, with the new id in `to`; supports `group=change|document` and `as=counts` with an optional `by`; and `since=previous` never picks the summary itself, a same-day sibling or a predecessor git mistakes for a rename. Labels of these blocks a config leaves out come in its `language`.
- db1b76c: Two generated blocks that read git: `trove:branches` lists the branches of a code root that match a pattern, with the commits not in each base and the date of the last commit; `trove:changes` lists the items closed, added and moved since the previous summary of the same kind, a date or a commit. Git is read once per run, only for documents that hold such a block.
- 64cc899: Items have a `drift` field: `true` when a code file the item's own section links to changed in its root after the document's `checked` date, at the root's `ref` or else at `HEAD`. It filters queries, blocks and MCP queries (`drift=true`), and a `drift` column in a generated block names the changed files. Git runs only when a query, block or report uses the field, once per code root.
- 77795b3: `trove item recheck <id...>` (also `--drifted`, filters, `--unchanged` for code changed in whitespace alone, and `trove_item` action `recheck`) writes the commit an item's code is at into its own `checked` column, and drift counts from there. Drift tells `drift=file` apart: a file whose named lines are unchanged but whose other lines changed. A new `stale-check` rule, off by default, flags open items not re-checked within `limit` days or before `commits` commits touched their code.
- 23ef8a5: `ledger.heading` and `ledger.stub` shape the section `item add` writes; closing or deferring keeps a parenthesis that is part of the title.
- 3e63787: A ledger cell of `—`, `–` or `-` reads as empty everywhere: `item-enum` skips it, filters match it as an empty field and groups put it under no value. A ledger column with `multiple: true` takes comma-separated values: `item-enum` checks each, filters match any of them, and counts, trend and report groups count the item under each value.
- 3798deb: `trove links --fix` keeps dead links into code that git deleted pointing at its last version: a GitHub or GitLab permalink at the parent of the deleting commit, or a `*(deleted in <sha>)*` note that `dead-link` checks at that commit. `trove links --dead` ends with `N dead of M links`.
- e40fe3a: `trove item move`, `trove links` with the `dead-link` rule (code links checked under `roots` present on the machine), `trove export` to CSV or JSON, and `migrate --project` records the project as a code root.
- e40fe3a: Generated `<!-- trove:items|documents|counts|placement … -->` blocks in any hand-written document, refilled on every edit and report, frozen once archived, with a `filter:` header as their base. Summaries become kinds: `trove summary new <kind>` creates a dated `summary` document from the kind's template with blocks filled and `<!-- write: … -->` places for the analysis (`write-place` rule); `trove summary show` prints one without writing. Rebase conflicts inside generated blocks settle themselves.
- e40fe3a: `trove mcp`: a stdio MCP server with eleven tools over the same operations (query, show, check, regulation, prompt, create, update, transition, item, report, sync) and resources for the regulation, the config and type templates.
- e40fe3a: `migrate` fits archives that do not look like the presets: ledger columns from the archive's own tables (per type when they differ), no status line where documents have none, status keys as labels when documents write keys, finished statuses the archive keeps (`archive.finished`), and no empty reports. `ignore` takes path globs; text inside inline code is no longer read as a link.
- 812ae0d: `trove migrate` keeps the archive's remote off the store and prints it with a ready `trove remote add` command, a warning that pushing there turns the archive's repository into the store, and how many archive commits that remote does not have yet.
- 23ef8a5: Migration no longer narrows the rules to what the documents happened to use: priorities get the whole `P0`… scale, statuses keep the preset's, fields every document of a type has become required, status lines go from every type when no document has one, a type whose documents lack the id fields gets a template read off its ids, and the notes list each inferred vocabulary. `id-format` reports a document that lacks a field its ids need.
- e40fe3a: `trove migrate <archive> <store>`: builds a new store from an existing archive with its git history and uncommitted work, a config fitted to the documents, rebuilt reports and a before/after count. The archive is only read.
- e40fe3a: What goes where: each type gets a `purpose` in the config, `trove regulation placement` lists them, a `<!-- regulation:placement -->` block in AGENTS.md is rebuilt from them, and `trove doc retype` turns a document into another type with its folder, prefix, status, title, links and references following.
- 3943a04: Plan stages: a type with the new `stages` capability (plans in both presets) reads its first task list or table with a status column as stages, exposed as the fields `progress` (`3/5`), `next` and `bar` (`3/5 ▰▰▰▱▱`) for filters, columns and reports, and listed by a `<!-- trove:progress … -->` block. The status column names and done values are set by `stages:` in the config, with English and Russian defaults. Existing stores add `stages` to their plan type's capabilities.
- 768dc4a: Presets add a `checked` ledger column, so `item recheck` works in a new store without config edits.
- 3b8238a: The project tree stays clean by default: `init`, `store add` and `migrate --project` link the store in `.git/trove.yaml`, `trove clone <store-url>` clones and links a store the same way, a store next to the project whose `roots` name it is found without any link, and `--share` writes the committed `.trove.yaml`. Git runs with stdin closed, so the MCP server over stdio no longer loses input to it.
- ecb59a9: `trove query` takes `--limit`, `--offset` and `--brief`, and `trove_query` takes `limit` (100 by default), `offset` and `brief`; a cut list ends with a note saying how to read on. The MCP server keeps the parsed store between calls, drift caches its git reads by commit in the store's git folder, and opening a store by path no longer asks git for the project.
- a4cea5f: `trove refresh [doc...]` refills generated blocks, a summary past its date too; `summary new --from` keeps the template's structure and carries written places over by the heading or block above them; `query documents` fills a `document` column.
- 23ef8a5: The audit addendum is now the `resolved` type (`AUDIT_X.RESOLVED.md`, capability `resolved-of`): with `closeInto`, `item close --as <outcome>` moves the row into its closed-items ledger of the same columns and the section below it, creating the companion on first use and archiving it with the audit. `ledger.closed` is a map of outcomes and `ledger.note` marks the heading; `show` finds closed items and, without a ledger row, every section titled by the id; closed items stay out of queries unless a filter names `state`.
- 2b9fa3b: `trove resync --seal` closes a finished move: after the last resync it writes `MOVED.md` and a first line in `AGENTS.md` into the archive and commits them there. `trove doctor` shows the migrated-from archive and warns when it changed after the last resync.
- e40fe3a: `trove resync` brings changes made in the migrated-from archive into the store three-way, keeping the store's own edits and following documents it archived; conflicts wait for `trove resync --continue`.
- e40fe3a: A code root may name a git ref, `roots: { app: { path: ../app, ref: origin/main } }`: links into it are checked at that commit instead of in whatever branch is checked out.
- e40fe3a: Ledgers with several tables: `{section}` in `ledger.id` with `ledger.sections` gives every table its own id code (`DEBT-S3`, `DEBT-I2`); `item add … section=<heading>` and `item move --section` pick the table, and new item sections land after that table's last one instead of the end of the file.
- 8aebc4d: `trove schema` prints the JSON Schema of `trove.yaml`, generated from the config schema and committed as `schema/config.schema.json`; `init` and `migrate` start new configs with a `yaml-language-server` line pointing at it. `trove serve [--port N]` opens a read-only dashboard on 127.0.0.1: documents and items with `query` filters, a document's text, live summaries.
- e40fe3a: Stores: `init` (English and Russian presets, git with a pre-commit check, `.trove.yaml` pointer, machine registry), `clone`, `store add` with scopes, `doctor`, `forget` and `migrate` from an existing archive into a new store. Commands find their store from any project folder.
- e40fe3a: Summaries: `summaries:` in the config builds filtered status documents (counts, open items by document, documents in work) that every edit rebuilds; `trove summary` and `trove_summary` render one on demand. Filters gain `~substring`, globs and `!` exclusion everywhere, and items filter on their document's fields.
- e40fe3a: Sync: by the store's `sync` mode every operation makes one commit and, with `push`, pushes it; a moved remote is rebased over, conflicts in generated reports are rebuilt, conflicts in hand-written documents stop with the file named. `trove sync` commits hand edits with rebuilt reports; `trove remote add <url>` connects a local store.
- 5e1e7bc: `summary new --from latest` finds each write place by its `<!-- write: … -->` line first, so text survives a block added above it; the line now stays above the written text, and `write-place` only reports places with nothing under them. `trove:changes since=<date>` follows the main line instead of an older commit of a branch merged later, and a new summary that replaces one of the same day starts `since=previous` from that one. `trove:branches active=30d|6w|3m` hides branches with no recent commits. New `trove:trend weeks=N by=<field>` block: items opened, closed and open at the end of each week, from the ledgers' history.
- 04fe048: `changes` moves a start from before the store existed to its first commit with a note line, counts archived documents' items as closed and says `no changes` when empty. `trend` marks the week the store came in as `at start`, counts moves in their own `moved` column, groups items without the `by` field by their document's field or `fallback=<field|section>`, and filters `path` by where the item was that week.
- e40fe3a: Types may bring their own ledger (columns, statuses, id template), a document may hold several ledger blocks, and every item knows the heading above its table as `section`. A new `study` type covers investigations still under way, apart from finished `research` reports.
- d97908d: A `verify-cmd` header field holds a shell command, with `{root:<name>}` and `{store}` paths, that exits 0 while what the document says still holds. `trove check --verify` runs those of the documents in work in parallel, with `--jobs` and `--timeout`, and exits 1 when one fails; the last result per document is kept in `.trove/cache/` and shown by the `verified` column of `documents` blocks and queries.
- 201d154: `blocked_by` and `until` on items and documents with a computed `waiting` field and the `wait-refs` and `deferral-lifted` rules; documents give `note`, the status line after the status word, and take `owner`; presets limit the statuses of plans, specs and studies, and migration keeps the ones documents use; `summary new` archives the summary it replaces, and `--from latest` carries its written analysis over.

### Patch Changes

- f47e2c8: A status that `lifecycle` archives a type under, such as a closed plan, is allowed in the archive and kept by `doc archive`; `doc archive --status` (and `trove_transition` with `status`) closes and archives in one step.
- ceed35d: `summary new --from` finds the text after a block by the block's kind and place under its heading, so changed options keep it, and falls back to a block of the section the template dropped; `changes` filters a closed or moved item also by the document it was in at the start, and `as=counts` honours `group`.
- a867c1f: `summary new --from` keys the text after a block by the block's opening line, generated blocks rebase relative links in copied text, a `--name` that already has the prefix is taken whole, and `item recheck` changes only the rechecked rows.
- fb667a5: `changes` counts closed and moved items in the document they were in at the start, and a moved item's `document` cell reads where it was → where it went. `summary new --from` fills a write place that now sits below a new block with the text of the block above it.
- e40fe3a: Generated reports and new summaries write a status line only when their type has the `status-line` capability.
- 3b64123: `changes` and `trend` count an item absent at the start and closed now as closed only when its heading note dates the closing on or after the start, or names a later store commit.
- 3bf11af: `doc new` transliterates Cyrillic topics (Russian, Ukrainian, Belarusian) into the file name and keeps the first eight words of long ones.
- f3961e4: `links --fix` resolves an SSH alias to its real host before building a permalink, pins a file the root's ref never had at the last commit of another branch or tag (`*(at <sha>)*`), and names the ref when a file is in no branch; `--dry-run` diffs show only the changed lines of long files.
- 3be20e6: `item move` out of a type with `closeInto` leaves a `moved` row in the source's closed ledger that names the new id.
- 23ef8a5: A new document gets a status line only when its type has the `status-line` capability; header values in double quotes escape `\` and `"`, so Windows paths stay valid YAML.
- bd13cab: An item's edits find the heading that starts with its id before one that only mentions it; a new resolved companion takes its required header fields from the audit.
- 7e69aef: `query`, `export` and `trove_query` show only the columns of the ledgers the matched items come from, `id` first; `--columns a,b` picks them (`--fields` still works).
- 2b9fa3b: `trove resync` follows a document the archive moved into its archive folder as one `moved` line, moving it in the store too and keeping the store's own edits, instead of two `applied` lines.
- e40fe3a: Config YAML errors now point at the line. MIT license.
- 47fb962: Stores under a symlinked folder, such as the macOS temp folder, are found and synced: repository roots keep the caller's spelling and paths compare by their real target.
- 4ac08ee: Sync rebuilds reports and checks the store against the same date as the operation it records.
- 0f037c8: A custom template leaves a declared field that was not given empty instead of keeping `{{field}}`, and refuses placeholders that are not fields, naming them.
- b16edca: Archiving a never-committed document commits its new place instead of failing on the old path; a code link missing at the root's ref but present in its checkout is `unmerged`, not dead.
